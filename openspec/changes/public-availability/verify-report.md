**Lead-time skip-window judgement (the brief's focal point).** The skip fires only when
`lt_close > lt_open AND expected_first > last_start`. With the close clamped to `24:00` and a 30-minute service,
`last_start = 23:30`; `expected_first` (the first grid step at or after `now+30`) exceeds `23:30` once `now+30 > 23:30`,
i.e. `now > 23:00`. The skip window is therefore the last 60 minutes before local midnight. This is **correct and
justified, not a hidden gap**: inside that window the last start today can hold is `23:30`, so no today slot can
satisfy `start >= now+30` and the rule is genuinely unobservable — neither the rule nor its violation can be seen. The
classifier's first conjunct (`close > open`) is the guard against a broken construction masquerading as an unprovable
clock: a wrapped window (close behind open) falls through to the loud non-vacuity guard, which fails the suite. The
6b sweep proves the classification over all 48 synthetic clocks and pins the boundary precisely (`23:00` still has an
eligible start, `23:30` is the unprovable case). At the actual run clock (BA 2026-09-21 ~22:51), the section-6 guard
was genuinely exercised (non-vacuous), not skipped. The 60-minute window is narrow and honest; a 30-minute window (the
subset where `now+30` itself crosses midnight) would have hard-failed a correct implementation at, e.g., 23:15.
